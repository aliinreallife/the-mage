- **زمینه:** اسناد تاریخچه‌ای در `docs/` پراکنده‌اند، PRD واحد وجود نداشت و ورود agent جدید به دانش قبلی وابسته بود.
- **بررسی و دلیل:** کاربر راهنمای مستقل چهار فایلی، تشخیص نام پروژه، بازسازی بدون حذف و نگهداری مستمر را صریحاً ارائه و اجرای آن را خواست.
- **تصمیم:** تنها ساختار مرجع محصول/توسعه در ریشه `the-mage-docs/{PRD.md,decisions.md,status.md,how_to_update_docs.md}` است. اسناد تخصصی/شواهد قدیمی فعلاً حفظ می‌شوند و مرجع سابقه‌اند. PRD بازسازی‌شده تا پذیرش صریح پیش‌نویس است.

## D-006 — نوع کارت‌های ارتقا مستقل از کمیابی Artifact است

- **تاریخ و وضعیت:** 2026-11-17 | معتبر به‌عنوان درخواست صاحب محصول؛ **پیاده‌سازی هنوز فقط در PR #16**.
- **زمینه:** کارت‌های لول در کد main از Common/Rare/Epic/Legendary استفاده می‌کنند؛ این عنوان‌ها برای توانایی‌های معمول در پژوهش 0.9941 تأیید نشده‌اند.
- **بررسی و دلیل:** درخواست صریح صاحب پروژه برای بررسی نوع Active/Passive/Elite؛ دادهٔ منبع دسته‌های Magic/Passive/Special Passive/Trait/Combination را مشخص می‌کند؛ Elite ردهٔ دشمن است، نه ردهٔ عادی کارت.
- **تصمیم:** کارت‌های لول باید نوع واقعی توانایی را نمایش دهند، نه rarity وابسته به rank؛ rarity مختص Artifact باقی می‌ماند. نسبت‌دادن Special Passive و فهرست شانس native تنها با شاهد معتبر مجاز است.
- **مبنا و منشأ:** درخواست کاربر و `docs/reference/`، تغییرات `src/components/LevelUp.tsx` در PR #16.
- **جایگزینی / بازنگری:** رفتار `main` تا merge/تست PR هنوز منطبق نیست؛ تسک باز در `status.md`.

## D-005 — بازسازی مکانیک با مرجع قابل‌راستی‌آزمایی، نه حدس

- **تاریخ و وضعیت:** 2026-11-14 (تأکید مجدد؛ تاریخ اصل تصمیم نامشخص) | معتبر.
- **زمینه:** بازی فاز اول قابل اجراست اما فرمول‌های آن تقریب‌هایی دارد که با مرجع 0.9941 برابر نیستند.
- **بررسی و دلیل:** سنجش نرخ برد بات‌های خودمان همسانی با بازی مرجع را اثبات نمی‌کند؛ دادهٔ استخراج‌شده نیز لزوماً زمان‌بندی واقعی اجرا را نشان نمی‌دهد.
- **تصمیم:** قواعد عددی با شواهد `stored`، `inferred`، `static_verified`، `runtime_verified` و fixture جدا بازسازی شوند. تغییرهای اثبات‌نشده در `src/game/reference/` و شاخهٔ مجزا باقی بمانند؛ `main`، checkpoint و خروجی Android ناخواسته تغییر نکنند.
- **مبنا و منشأ:** `docs/DECISIONS.md` بخش «Reaffirm original mechanical-fidelity mandate»، `AGENTS.md`، و تأیید مسیر PR #16.
- **جایگزینی / بازنگری:** با فراهم‌شدن شواهد جامع، قطعات تأییدشده می‌توانند مرحله‌ای به بازی اصلی منتقل شوند؛ نامشخص‌بودن زمان‌بندی به معنی parity نیست.

## D-004 — APK آزمایشی Capacitor برای اندازه‌گیری، نه مهاجرت موتور

- **تاریخ و وضعیت:** 2026-11-14 | معتبر.
- **زمینه:** هدف Android است اما کارایی WebView و امکان native port هنوز روی دستگاه واقعی معلوم نیست.
- **بررسی و دلیل:** مقایسهٔ TWA/WebView و موتور native بدون دادهٔ FPS، لمس، RAM/GC، گرما و بازگشت برنامه نتیجهٔ معتبر ندارد.
- **تصمیم:** بستهٔ offline از Vite/Capacitor 8 با شناسهٔ موقت `ir.themage.debug` یا `ir.themage.preview` برای benchmark بسازید؛ آن را APK آزمایشی بنامید نه native gameplay یا release قطعی. مکانیک مستقل از renderer باقی بماند.
- **مبنا و منشأ:** `docs/DECISIONS.md`، `docs/ANDROID-TESTING.md` و `.github/workflows/android-debug.yml`.
- **جایگزینی / بازنگری:** تصمیم بستر نهایی پس از تست واقعی Android.

## D-003 — GitHub منبع توسعه و بسته‌بندی بازتولیدپذیر است

- **تاریخ و وضعیت:** 2026-11-14 | معتبر.
- **زمینه:** خروجی بعضی محیط‌های قبلی PNG و دارایی‌های باینری را ناقص منتقل می‌کرد؛ release لازم است قابل‌تولید مجدد باشد.
- **بررسی و دلیل:** ذخیرهٔ mirrorهای باینری در `assets/embedded/` و restore در pipeline، وابستگی به فایل‌های محیطیِ موقت را کاهش می‌دهد.
- **تصمیم:** سورس و CI از GitHub؛ build و آزمون در Actions؛ آرشیو release، certificate، credential و دادهٔ خصوصی در Git ثبت نشوند. زمان build از منابع tracked asset بازسازی شود.
- **مبنا و منشأ:** `docs/DECISIONS.md` بخش «Initial repository migration»، `scripts/binaries.mjs` و workflowهای CI.
- **جایگزینی / بازنگری:** در صورت تغییر سیستم asset، قابلیت rebuild و عدم افشای secrets باید حفظ شود.

## D-002 — تجربهٔ Android-first و حفظ موقت معماری فعلی

- **تاریخ و وضعیت:** 2026-11-14 (بازگویی تصمیم قدیمی؛ تاریخ آغاز نامشخص) | معتبر در محدودهٔ پلتفرم.
- **زمینه:** بازی قابل‌اجرای React/Canvas و تجربهٔ فارسی پیشاپیش وجود داشت.
- **بررسی و دلیل:** بازنویسی موتور بدون سنجش عملی، کارایی را تضمین نمی‌کند و خطر از دست رفتن رفتار/save فعلی دارد.
- **تصمیم:** Android هدف است؛ UI فارسی RTL عمودی؛ نسخهٔ فعلی React/TypeScript/Vite/Canvas 2D نگه داشته می‌شود تا مهاجرت احتمالی مبتنی بر داده باشد.
- **مبنا و منشأ:** `AGENTS.md`، `README.md`، `docs/DECISIONS.md`؛ کد `src/App.tsx`.
- **جایگزینی / بازنگری:** اگر تست واقعی تصمیم متفاوتی توجیه کند، برای معماری جدید تصمیم مستقل ثبت شود.

## D-001 — هدف همسانی مکانیکی با Magic Survival نسخهٔ 0.9941

- **تاریخ و وضعیت:** تأکید مجدد 2026-11-14؛ تاریخ تصمیم اولیه نامشخص | معتبر دربارهٔ **مکانیک**؛ **حدود هویت بصری در اختلاف**.
- **زمینه:** اسکلت فعلی دارای چهار قهرمان و محتوا/بالانس محلی است ولی محصول نهایی قرار است از نظر مکانیک به نسخهٔ مشخص 0.9941 نزدیک شود.
- **بررسی و دلیل:** استفاده از مقادیر تأییدنشده یا صرفاً مشابه از نظر نام/احساس بازی، هدف دقت عددی را محقق نمی‌کند.
- **تصمیم:** فرمول‌ها، ترتیب اعمال، گزینه‌های انتخاب، enemy/waves، progression و RNG تا سطح شواهد معتبر بازیابی شوند؛ اختلاف نسخهٔ محلی با مرجع آشکار باشد. بخش طراحی بصری و بازاستفاده از assets شخص ثالث بدون تصمیم روشن و حق استفاده تغییر نکند.
- **مبنا و منشأ:** درخواست‌های صریح کاربر، `AGENTS.md` و `docs/DECISIONS.md` (2026-11-14).
- **جایگزینی / بازنگری:** **تعارض باز:** مدارک مخزن بر «هویت و asset مستقل» تأکید دارند، در بعضی درخواست‌های پیشین شباهت بصری کامل مطرح شده است؛ اعتبار و دامنهٔ نهایی در T-004 پیگیری شود.
