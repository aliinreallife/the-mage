# Project decisions

## 2026-11-16 — Source leveling V1 is development-only and event-driven

- Source-indexed mana thresholds and the static-code-derived choice lifecycle are integrated into the actual Game behind `?ref-leveling&limitRatio=…` **only in non-production builds**. The limit ratio must be explicitly supplied and is not claimed as a verified default.
- Each collected gem triggers one explicit source leveling call; no eager multi-level loop. Primary level changes only after a successful ordinary card and mode2 cost refresh. The origin of gem input and Unity post-choice scheduling remain unknown and are not guessed.
- The experimental session is intentionally **not serialized** into the existing checkpoint format. Old saves, checkpoints, rewards and unlocks remain isolated; no Android production exposure.
- This is a bridge validation milestone, **not** full source-game parity or permission to enable the new engine globally. See [the source-leveling integration guide](reference/PLAYABLE-LEVELING-V1.md).


Keep durable architecture and gameplay decisions here. Add a dated entry for each substantial change.

## 2026-11-14 — Reaffirm original mechanical-fidelity mandate

- **Product target since inception:** a mechanically faithful recreation of Magic Survival **0.9941** with original branding/presentation and idiomatic Persian/Iranian localization. This is a reaffirmation of the original brief, **not a change of product direction**.
- Match recovered numerical equations, application order and stacking, spell behavior, content prerequisites, artifacts, enemy AI and waves, progression and reward probabilities. Reconstruct missing behavior through evidence-driven research; never call approximate mechanics parity-complete.
- Existing four-hero Phase 1 gameplay is a technical foundation and working testbed, **not the final feature/content scope**.
- Historical balance-bot win-rate optimization is not a fidelity benchmark; compare against verified reference mechanics and deterministic fixtures.
- `src/game/reference/` remains a non-production integration sandbox until enough reference rules are verified. Correct and validated implementations are intended to become normal gameplay incrementally.
- Persian/Iranian text, cultural presentation, art, sound and branding remain independently authored and do not license third-party copyrighted creative material. Cultural adaptation must preserve functional mechanics.
- Keep a research evidence trail and record uncertainty (`stored`, `inferred`, `static_verified`, `runtime_verified`); source data alone may not establish effective runtime values.

## 2026-11-14 — Android wrapper as a benchmark, not an engine migration

- Add a **separate debug-APK build path** using Capacitor 8 and the current Vite `dist/` output. Keep the production PWA and all existing native-derived reference kernels unchanged.
- This is an **offline-packaged WebView evaluation** using temporary package ID `ir.themage.debug`. No store signing, release-ID commitment, hosted origin, or native-renderer claim.
- Benchmark an actual device before committing to either a web renderer or a Godot/native port. Track heavy-combat sustained frame time, 1% slow frames, touch latency, heap/GC spikes, heat, pause/resume, and airplane-mode restart.
- Maintain game-mechanics/data parity independently of the renderer so a future engine change can reuse validated equations, inputs and fixtures.
- TWA could wrap a hosted PWA, but it uses the browser to render game content and is not inherently faster than the same browser game.

## 2026-11-14 — Initial repository migration
- Source of truth: the user-provided `the-mage (11).zip`.
- Android-first product, Persian RTL UI, engine-agnostic future. Existing React/TypeScript/Vite/Canvas 2D implementation is retained.
- Production gameplay remains as built; Magic Survival 0.9941 data is accepted only through the experimental, evidence-aware reference layer until verification.
- Track autogenerated binary mirror files under `assets/embedded/` because Arena workspace exports previously omitted PNGs.
- Release ZIPs, temporary certificates and generated output are not tracked in Git. GitHub Actions should build reproducibly.
- Physical Android validation and human playtesting remain outstanding.
